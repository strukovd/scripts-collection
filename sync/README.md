# Синхронизация настроек Ubuntu

Скрипт работает на Node.js без npm-зависимостей. Файлы берутся из ветки `master` репозитория `strukovd/scripts-collection` через HTTPS. Сначала опубликуйте изменения в GitHub: удалённый запуск читает именно опубликованную версию.

```bash
curl -fsSL https://raw.githubusercontent.com/strukovd/scripts-collection/master/sync/run.js | node
```

Перед первым запуском можно посмотреть план:

```bash
curl -fsSL https://raw.githubusercontent.com/strukovd/scripts-collection/master/sync/run.js | node - --dry-run
```

Если локальная версия одного из `PULL`-файлов отличается, скрипт пропустит её и завершится с кодом 1. Для замены используйте `node - --force` вместо `node`. Перед заменой рядом с файлом создаётся копия с суффиксом `.sync-backup-*`. `--dry-run --force` показывает, что изменится, без записи.

Задачи задаются в массиве `TASKS` в `run.js`:

- `PULL` копирует целый файл. Существующий файл с отличиями сохраняется, пока не указан `--force`.
- `APPEND` добавляет управляемый блок в конец файла.
- `PREPEND` добавляет управляемый блок в начало файла.

Управляемые блоки при следующих запусках обновляются по маркерам. Существующий файл перед их изменением также копируется в резервную копию. `source` указывается от корня репозитория, `dest` — абсолютным путём либо путём от домашнего каталога (`~/...`). Запуск не требует ввода с клавиатуры, поэтому подходит для передачи скрипта в `node` через pipe.

Текущие задачи скачивают файлы в `~/.bash/` и добавляют в `~/.bashrc` блок их подключения. Если в вашем `.bashrc` уже есть строки, вручную подключающие эти файлы, уберите дублирование. В `.bash_custom_env` сейчас есть пути, зависящие от конкретного компьютера; проверьте их перед использованием на другом ПК.
